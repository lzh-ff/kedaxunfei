# 技术实现、原代码关系与复现

## 当前运行结构

`用户输入 → 浏览器状态 → 结构化知识 / 规则 / 数值计算 → 分步解释、图表、诊断 → 学习者笔记与导出`

页面是原生HTML/CSS/JavaScript模块。`src/engine.mjs`包含计算、知识检索、对话话题、任务生成和诊断；`src/views.mjs`负责显示；`src/app.mjs`负责输入事件、状态和导出；`data/knowledge.mjs`、`data/curriculum.mjs`分别维护内容与课程结构。运行时没有第三方CDN脚本或付费模型服务。

GitHub Pages只负责静态文件托管，不执行Python。评审不需要API密钥。当前是规则与知识检索MVP，不能称为已部署的LLM/RAG推理服务。代码里没有秘密、真实学生记录或原始报名材料。

开发前检查了用户提供的压缩包：

- 既有PPT提出专业内容推荐、可解释计算、执行反馈与教学协同。此MVP沿用“经世智学”定位与分层执行思路，把范围收敛到电商运营实训。PPT中的统计与模型基准不作为本MVP实测成绩。
- 人岗匹配包有13个PyTorch源码文件，未提供配套推理权重和完整业务服务。本MVP没有加载这些模型，不展示伪造匹配分数。
- Python资料包主要是课程课件和习题，未直接导入本项目经济学知识库。

本网页应用是新增实现；没有把MetaGPT原框架重新标为原创，也没有将其配置文件或报名PDF上传公开仓库。

## 定价模型

潜在需求：`Q(P)=Q0*(P/P0)^(-epsilon)`。

本期可实现销量：`min(Q(P), capacity)`；允许连续期望值，界面展示时四舍五入。收入：`P*Q`；成本：`unitCost*Q+fixedCost`；利润为收入减成本。

基准利润采用同一成本和库存约束，只将售价换成基准售价100、基准潜在销量1000。理论保本量为`fixedCost/(P-unitCost)`，固定成本为正且单位贡献不为正时返回`null`；固定成本为零时另分“所有销量保本”与“仅零销量保本”。若保本量超过库存，即本期约束下不可达到。

此函数不是训练得到的真实需求模型。未分别计入税费、退款、抽佣、跨期库存、竞品回应和现金流。输入区间验证、NaN和Infinity拒绝由计算层执行。

## 偏好实验

依据用户本地 `发放放.pdf`：《大型语言模型智能体与理性及道德偏好的对齐：一种监督微调方法》，yile wang，2026-08-08，第3.3节公式(1)，PDF第10—11页。未核实其公开发表状态，也没有公开再分发论文全文。

原文使用含α、β、κ的偏好模型。本实验设α=β=0，改为单阶段同时行动囚徒困境，固定T=5、R=3、P=1、S=0：

`U(C)=(1-kappa)*(q*R+(1-q)*S)+kappa*R`

`U(D)=(1-kappa)*(q*T+(1-q)*P)+kappa*P`

比较两个效用，返回合作、背叛或并列。该运算不包含SFT、模型推理、论文的顺序博弈协议、重复双寡头模拟、实验统计或真人测试，不能声称复现整篇论文。

## 对话与学习诊断

知识检索对标题、标签、中文双字片段评分；未知话题返回范围提示，模糊初始问题提供选择，后续“例子/解释/来源”复用当前知识话题。包含关键词的促销利润问题读取当前参数进行计算。回复中的来源ID必须对应来源表。

六题分别对应六个能力，未答与错误分开；学习建议优先链接本次错误维度。它是教学诊断示例，不声称具有心理测量效度或专业认证效力。

记录用`localStorage`保存在当前浏览器，版本校验与输入校验失败时恢复默认。用户文本显示经过HTML转义；导出文件用Blob在浏览器内生成，不上传用户记录。

## 本地复现与适配

`npm ci`安装固定版本测试依赖；`npm test`运行核心测试；`npm start`启动本地静态服务；`npm run test:e2e`在已安装的Edge中运行交互检查。运行时代码本身没有NPM依赖。

新增相近岗位时：在课程数据中定义岗位能力、典型任务、资源与问题；补充有来源的知识条目；按对应行业改写计算假设；重新验证来源映射与任务闭环。修改知识库许可范围前核查原始授权。

如后续接入MetaGPT或其他模型，需要单独运行服务器接口，保管模型密钥、限制请求并验证引用，不可将密钥写入Pages。该后端不在当前版本中。
